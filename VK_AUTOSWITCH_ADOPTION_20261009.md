## Remaining readiness

Module adoption is established; ordinary compatible worker/prompt/history updates
use validated immutable releases and atomic publication at the next execution
boundary. Native safety/lifecycle changes and incompatible protocols still require
backend adoption. VK::Staging owns live publication and deployment; development
owns implementation, packaging and validation.

Adoption is not evidence of savings. Recommend retains actual models, and the
first post-cutover work is dominated by cutover/control-system tasks. The next
useful evidence is current-step recommendations from ordinary real work,
especially read-only follow-ups in historically protected chats. Investigate
operational context being mistaken for a protected change before widening any
qualification. Count classifier, initial/recovery and child usage in eventual
accepted-task savings. Do not infer allowance weights from API prices.

The deadline remains **October 30, 2026**, before included allowance drops from
20x to 10x. Remaining dependencies are useful cheaper Recommend decisions on real
work, preserved protected-risk behavior, quality/net-usage evidence, and separate
owner authorization before enabling Auto. No owner manual command is needed.
