## Implemented controller and binding rules

`scripts/deployment/vk_candidate_generation.py` has no operational CLI or default
adapters. A newly sealed owning supervisor supplies independently verified
writer-fence and acceptance receipts; a pinned provider supplies authenticated
Desktop-B full-current manifests and member streams. These contracts are not
implemented by the fixture adapters and cannot be replaced by caller-supplied
"success" JSON for production. Root must bind actual implementations and evidence.

- Layout validation rejects overlap with protected roots and host symlink aliases.
  Restore uses an initially absent candidate tree and verifies all member bytes,
  SQLite integrity and complete included metadata. It refuses unknown/foreign
  ownership mappings, privileged modes, special files, external hardlinks,
  unresolved/cyclic links, missing xattr/mtime proof and non-user xattrs requiring
  a reviewed adapter. Snapshot sidecars must be normalized by the provider.
  The built-in equality proof covers mode, uid/gid, mtime, links and user xattrs;
  it does not certify atime, ctime, birthtime or filesystem inode flags. The
  supervisor must explicitly account for all required Linux metadata in its
  bound acceptance receipt and refuse full-state acceptance when any requirement
  is unsupported. Restored inode allocation/ctime differ from the original by
  construction. This is an explicit proof limit, not an omitted preservation claim.
- A source/scope/capture-bound measured capacity policy must be pinned before
  restore or catch-up. The sealed supervisor supplies OP's actual reserve/peak
  evidence; this module checks available bytes and working reserve while streaming.
  Missing policy or insufficient headroom blocks before restore. Fixture reserve
  values are not production floors.
- Virtual absolute links resolve against the candidate namespace. The helper
  augments a pinned reviewed kernel command with containing virtual-root mounts;
  it requires user/PID/network isolation, hidden host manager runtime, read-only
  host root and no extra writable host binds. It preserves the virtual-to-physical
  bindings through promotion. Environment overrides alone authorize no launch.
  Actual worker/supervisor/socket proofs must be rerun with the full mapping.
- Accepted rehearsal is followed by a fresh full-current B capture under held
  incumbent/all-writer fencing. Candidate/test writers must be stopped first.
  Catch-up compares complete inventories, retains displaced paths/test changes
  in quarantine, closes hardlink groups, and streams authoritative changed data.
  It never unlinks or overwrites live work or silently merges test edits. Files,
  links, metadata and directories are sealed durably, then verified again.
- Activation requires the same root, exact scope/source/manifest/capture receipts,
  runtime identity, real packaged scanner/module/controller acceptance, consent,
  preserved Recommend/usage controls and current delivered-report receipts.
  It also requires a pinned compatible latest-data fallback artifact. Fence and
  stopped-writer checks repeat before ownership. Intent is persisted first.
- Post-write fallback requires a fresh B capture originating from the candidate
  root. It normalizes/reconciles against that latest capture, retaining displaced
  mains/sidecars, then acquires compatible ownership on the **same latest-data
  root**. It cannot thaw the stale incumbent with its original data.
- PR153 namespace identity receipts use persisted DB dataset identity and actual
  candidate DB/workspace inodes. Regenerate them after catch-up. Missing dataset
  identity blocks; this code never enrolls it. Current incumbent lacks that table:
  root still needs the reviewed one-time enrollment/preparation path, preserving
  raw B state and binding any candidate derivation through final refresh. An inode
  pin from the initial restore cannot be reused after DB replacement.
- Retained journals prevent a fresh controller from silently taking ownership
  after a crash. Ambiguous partial refresh/activation requires explicit recovery
  evidence; it does not rerun, thaw or switch automatically. Cleanup is unavailable
  at every phase. Human QA plus a separate scoped implementation is needed to
  make it available later; no flag in this module unlocks deletion.
