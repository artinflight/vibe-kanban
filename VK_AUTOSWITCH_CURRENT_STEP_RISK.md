## Change

A follow-up may release inferred historical protection when its completed context
resolves the current step, semantic evidence says mechanical/bounded, localized,
established, short, low ambiguity and uncertainty, with an identifiable direct
validation method, no current risk and no safety-changing inspection needed.
The same evidence can replace a soft architecture keyword classification: recording
a settled design choice does not require designing the architecture again.
Large/open requirement surfaces and explicit validation restrictions keep their
existing behavior. No task examples or project-specific names are hard-coded.

The stable backend validates the native structured classification before accepting
this new bounded-step exception; a worker marker alone cannot grant it. Unknown
prior qualifications stay protected. Current deterministic/semantic protected
risks and validation failures remain intact. Generic “continue/proceed” resumes
retain the surrounding assignment, rather than silently continuing protected work
at a cheaper floor. A genuinely independent named assignment releases unrelated
history consistently in both built-in and module routing, without carrying that
old assignment into subsequent continuation of the new work.

Explicit operational prohibitions such as “do not deploy to production” or “no
production deployment” are masked only for deterministic risk matching. This is
not general-purpose negation. Positive deployment elsewhere, protected identifiers,
changes to safeguards, auth/security/data/concurrency risks and protected repository
evidence retain protection. A prohibition supplies no affirmative evidence that an
otherwise unknown task is cheap. The semantic instructions make the same distinction.

Existing qualification ranks, all seven represented models, model/effort proof,
manual locks/floors, exclusions, child hard floors, boundary escalation, dirty-state
handling, service tier, native IDs and the CU wire contract are unchanged.
The classifier remains Luna5.6/low, standard service; there is no extra inference
pass, retry or planning agent. Some formerly blocked requests can now receive the
existing classifier call, so future overhead must still be attributed alongside
accepted-task usage.
